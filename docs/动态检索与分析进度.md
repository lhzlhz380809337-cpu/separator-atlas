# 动态检索与分析进度

适用版本：0.5.1。本文同时说明实际能力、数据契约和后续维护方式。它不是现场问题的根因结论。

## 一次回答怎样改变下一轮排查

1. 对应上一轮的问题和选项。用户输入 B 时，优先采用明确保存的选项文字；旧问答没有选项字段时，尝试识别回答正文中的 A/B/C。无法对应就记为未知，请用户澄清，不猜含义。
2. 记录用户陈述的来源轮次、对应问题和回答含义。用户提出的问题、尚未实施的检查和不清楚的内容不算已取得的检查结果。
3. 将最新回答作为主要检索词，仍有效的近期陈述、原始问题和路线作为补充。已更正或存在冲突的陈述不再作为主动检索依据。首轮问题仍作为调查背景保留。
4. 在已入库并获准用于当前模式的知识中寻找片段。对照相关节点，沿实际图谱邻接关系补查最多两层，并读取这些关系所关联文章的片段。第二层需要与当前主题匹配，不遍历整张图谱。
5. 模型模式先用一次模型调用检查知识缺口和整理分析进度，允许提出最多两项本地补查请求。程序执行这些请求，重新组装受预算约束的材料，再用一次模型调用生成简短回答。两项请求在同一份计划中提出，不是无限循环自主调用。
6. 首次回答先用80—140字概述整体分析路线，再推进一个问题，整个回答限制在260个汉字左右；超长模型回答在服务端压缩到最多360字符。后续回答仍按对话协议通常两三句话、推进一个问题。用户要求解释、整理结论、节点总结或整理交接时可以展开。

本地引导也会还原选项、更新检索和执行图谱补查，但它仍按规则提问，不能代替模型理解任意自由表达。模型的补查计划采用普通 JSON 文本，不依赖厂商专用工具调用功能，兼容现有两种接口适配。

## 检索范围和数量

- 只使用显式入库的基础知识、详细图谱知识和知识投递条目；不扫描原始资料目录。
- 当前工序筛选与自建知识发送许可同时作用于关键词检索、补查请求、图谱关联文章和显式知识链接。
- 以相关概念和文章建立起点；优先查第一层相关边，最多五条，为第二层留空间；两层合计最多八条关系。先按图谱连接补查，再筛掉与当前主题无关的第二层路径。
- 两项模型补查各检索最多六个片段；合并、去重后最多二十四个候选片段，每篇最多两段。实际提供数量还受知识字符预算限制。
- 默认知识预算 16,000 字符，可选 5,000—40,000 字符。预算包含本段知识规则、机理关系与片段；会话、系统提示词和分析进度另计。字符不是 token，小上下文模型仍需选择较小预算、及时整理交接。
- 每条机理关系带上适用条件和核查方法。程序将这些条件交给模型判断，不宣称已经自动证明条件满足。
- 作者通过 `links` 或 `[[条目]]` 声明的链接属于主题关联，不能自动当成已验证因果。没有入库的关联正文不能被读取；缺口应保留。

目前仍采用术语和文本相关度排序，新增了真实的有限图谱遍历及模型提出的补查请求，没有引入向量数据库。检索排名不是根因概率；同样的知识在不同问题条件下，可能提供支持、反对或者仅供对照。

## 分析进度的字段与含义

服务器返回 `analysis_state`，会话文件在顶层保存这一份最新记录，避免每一轮重复存储完整进度。

| 字段 | 含义 |
|---|---|
| `version`、`initial_issue`、`turn` | 数据版本、最初问题、当前完成的问答轮次 |
| `facts` | 用户消息及其选项含义；包含 id、turn、prompt、answer、text、status 和 source |
| `hypotheses` | 候选原因及引用的支持/反对陈述 ID；只允许 candidate 或 weakened |
| `checks` | 用户报告已经执行的检查和结果，必须引用用户陈述，仍需核对条件 |
| `open_questions` | 尚未解决并影响判断的问题 |
| `pending` | 最后一轮待答问题与选项 |
| `retrieval_history` | 每轮检索词及最终提供的文章、关系标识 |

`facts.status` 的含义：

- `reported`：用户这样描述过，不代表已经独立核验。
- `unknown`：不知道、尚未检查、计划检查、问题尚未得到回答或选项无法对应。
- `superseded`：用户明确更正了原先说法，保留原记录及更正来源，不删除历史。
- `disputed`：陈述之间有冲突，需要澄清，不直接作为有效依据。

“检查过，未发现异常”是用户报告的阴性检查结果；“没有检查”是未知。两者不能互换。已更正、冲突或未知记录不能继续留在候选原因的支持/反对证据中。检查记录也不能单凭助手曾问过“检查了吗”就认定用户已经做过检查。

简单明确的否定更正在本地处理；复杂更正由模型提出旧、新陈述 ID 的对应，程序校验新陈述确实来自本轮，并保留原文供核对。语义理解仍可能出错，记录不是自动审核通过的现场事实。

结构化进度最多 500 条陈述、12 个候选、30 项用户报告的检查、12 项未决问题和 500 轮检索记录；进度总长度上限 250,000 字符。达到上限会提示保存与另建调查阶段，不静默丢弃旧记录。

## 模型补查契约

完整规则保存在 `agent/retrieval_protocol.md`。主要返回字段为：

```json
{
  "queries": [{"query": "本地知识补查词", "reason": "缺少什么机理、条件或核查方法"}],
  "supersede": [{"fact_id": "f2", "by": "f5", "reason": "本轮用户明确纠正了前述说法"}],
  "hypotheses": [{"id": "candidate_1", "text": "尚未验证的候选原因", "support": [], "against": [], "status": "candidate"}],
  "checks": [],
  "open_questions": []
}
```

这是字段示例，不能将示例 ID 当成现场证据。模型不得新增用户事实、写任意文件、指定可执行命令或通过该接口发起网络搜索。省略某类进度字段表示保留，空数组表示清空；`queries` 省略表示无需补查。

所有引用必须存在，候选不能标成 confirmed，补查请求不得超过两项。格式错误、超限或不合规内容导致该份计划不被执行，继续使用初次检索材料并显示提示。补查模型请求超时或服务错误时也尝试用已有材料生成最终回答；如果最终回答请求同样失败，则保留已有对话，提示本轮未完成。

普通模型问答通常两次服务调用：一次补查计划，一次最终回答。整理结论和交接只调用一次。没有对同一失败请求自动重试；降级后的回答是另一个用途的请求。费用与耗时可能高于旧版单次调用，每次网络等待上限仍为 90 秒。返回的 `retrieval_usage` 和 `usage` 分别记录计划、回答的服务端用量（服务未返回时为空）。

自建片段的正文、标题、章节名以及送出的关系元数据均经过常见敏感字段检查。该检查不等于完整脱敏，不能识别所有内部代号或可识别组合。外部搜索继续使用原有单独配置和许可，本地补查不自动触发外部流星。

## 星图上看到了什么

高亮由最终回答材料中实际包含的片段和关系决定，不把预算外的检索候选算作已阅读。补查计划阶段看到的初始材料不单独累计到最终高亮。含义是“本轮用于回答的依据”，不是模型内部注意力、读过全文、认可关系或已确认根因。

新进入本轮的节点短暂增强亮度，实际提供的关联线亮起。仅因两端同时点亮，不把一条未提供的主题链接画成已查阅路径。点击相关节点的“本轮查阅片段”，可查看片段、查阅缘由，以及相关关系的条件和核查方法。仍可另行打开当前完整知识正文。

历史回答的“点亮本轮依据”会恢复当时材料；新版进度文件保留当时的片段，即使知识库后续修改，也不会把旧依据悄悄换成新内容。旧文件只有关联标识时仍能恢复高亮，但不能凭空恢复当时未保存的片段。

## FTA 路径与分支边界

会话外层保存 `fta`：每个节点有稳定标识、父节点、建立时间、软删除状态和该轮完整问答；`active_leaf_id` 指向当前路径末端。新建另一条路径时，程序只取根节点到所选节点的问答，清空旧路径的结构化进度后重新构建，并把分支说明作为界面状态交给模型。旧分支仍保留，但不会作为当前事实混入新分支。

删除节点时，程序记录删除根节点、所有后续节点、删除前活动叶节点和时间。恢复使用该记录撤销软删除。Markdown 会同时输出树节点状态、删除/恢复记录、当前路径完整对话以及程序恢复数据。节点总结只读取指定路径，不写入当前会话。

## 保存、交接与恢复

0.5.0 使用 `separator-atlas-session` 第 2 版外层格式，增加 FTA 节点、活动路径和删除记录。程序仍接受第 1 版 JSON，并在载入时转换为单路径 FTA。第 2 版 Markdown 的末尾包含同格式恢复数据，因此可读、可被模型直接理解，也能由程序精确恢复。单文件最多 10 MB、500 轮，FTA 最多 1,000 个节点；仍建议阶段性归档。

载入时校验进度轮次与问答数量、初始问题、引用和字段长度；错误不会替换当前对话。模型设置、密钥、发送许可不从文件载入。结构化进度属于待核查的历史数据，其内容不能覆盖系统指令。

长对话采用人工核对过的交接记录后，完整问答与完整分析进度仍保存在本机。后续模型使用交接记录、本段问答、最近三十条进度陈述及当前候选直接引用的陈述；被省略的早期细节需进入交接记录或重新补充。不是把五百轮对话全部重新发送。

旧版记录缺少结构化进度时，可从仍提供的原始问答还原选项和陈述；只有摘要而没有早期原话的内容不能被程序冒充成已核验事实。接手人继续回答最后问题或补充新证据，系统再执行本轮检索。

## 维护和验收

核心实现分别在 `app/analysis_state.py`（进度与来源）、`app/retrieval.py`（检索与遍历）、`app/dialogue.py`（模型调用编排）、`app/web/dist/session.js`（保存与校验）、`app/web/dist/cosmos.js`（交互展示）。

回归场景见 `tests/test_dynamic_retrieval.py` 和 `tests/test_session.js`：连续 A/B/C、否定与未知、用户更正、非关键词关联文章、最多两层、条件保留、权限隔离、预算与高亮对应、错误计划与超时降级、进度往返、旧文件兼容。自动检查验证程序行为，不代表任何模型已经通过真实现场问题的专业验证。
