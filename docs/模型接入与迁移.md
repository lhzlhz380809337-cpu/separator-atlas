# 模型接入与迁移

## 两种使用方式

工作台内接入：在“模型设置”填写接口地址、模型名称和密钥。先“保存连接”，再“测试连接”，然后返回问题页调用。测试只发送一条通用连接消息；实际分析发送系统规则、当前问题、补充证据、检索知识与关系条件。可选复核会额外调用一次模型，增加耗时和费用；同一个模型复核自己并不等同独立专家审查。

0.6.0 首页普通模型问答通常分成两次调用：先按 `agent/retrieval_protocol.md` 整理进度、提出最多两项本地补查，再根据补查后的材料回答。使用普通 JSON 输出，不依赖厂商工具调用。格式错误或补查服务失败时，尝试使用初次检索材料回答并给出提示；不是无限重试。整理结论、FTA 节点总结和详细交接各调用一次。FTA 新分支只发送从初始问题到分叉节点的路径，并明确告知模型这是另一条路径。迁移时也带上该补查协议、对话协议和 [动态检索与分析进度](动态检索与分析进度.md)。

不依赖工作台：导出完整知识包，再按以下顺序组织其他智能体。

1. 将 `agent/system_prompt.md` 作为系统指令。
2. 按当前问题检索相关 Markdown，保留条件、测法和反证，不能只截取结论。
3. 从 `graph/` 补充一跳关系及其条件，从 `agent/playbooks.json` 选择合适剧本。
4. 加入 `agent/analysis_protocol.md` 的分析步骤，明确哪些是用户观察、哪些是一般机制。
5. 要求输出已知与缺失、候选原因、支持与反对证据、判别检查、验证和闭环。
6. 用 `evals/cases.json` 比较新旧模型，专业人员审阅答案后再用于实际辅助。

## 接口细节

Chat Completions：发送 `model`、`messages`、`stream:false`，读取 `choices[0].message.content`。支持文本内容或带 `text` 字段的内容列表。兼容接口并非统一标准；不同服务仍可能要求专属字段。

Responses：发送 `model`、`instructions`、用户 `input` 和 `store:false`，汇总 `output` 中的 `output_text`。`store:false` 不是所有服务对日志、保留或训练用途的统一承诺，应另核对所选服务的实际条款。

输入基础地址若没有路径则补 `/v1`，再补相应末端路径；已填写完整接口路径时不重复添加。对于自定义网关路径，请使用服务商实际提供的地址。远程地址要求 HTTPS，本机可使用 HTTP。程序拒绝接口重定向，避免凭据被转发到意外目标。

单次连接超时为 90 秒，不自动重试，以免未知状态下产生重复调用。模型截断会给出提示。两轮复核失败时保留第一轮结果并显示未完成情况。程序没有流式响应、图片识别、工具调用和厂商专用推理字段。

也可由启动环境提供 `SEPARATOR_BASE_URL`、`SEPARATOR_MODEL`、`SEPARATOR_API_KEY`。环境密钥只在规范化后的最终接口地址完全匹配时继承。不要在知识文件或可分享配置里填写密钥。设置对象的 `use_env_key:false` 可显式禁用环境密钥继承。

## 给较弱模型的组织方式

不要把整个知识库一次塞给模型。优先保留范围卡、测量定义、最相关的机制、三个可区分假设和下一步检查。问题复杂时可由使用者分两步提交：先核对对象与证据缺口，再基于补充证据做候选比较。每次补充证据后重建材料包，避免依赖模型记住未写明的条件。

当前检索是本地术语扩展和中文词片段相关度排序，不是语义向量检索，也不训练模型参数。检索分数只用于选材料。没有现场概率模型，所以不输出伪造的“根因概率”。

界面预算是知识字符数；系统提示词和用户输入另计。字符数不是 token 数，各模型分词不同。材料包显示总字符量，使用者还要为模型输出预留容量。复核轮额外加入草稿，容量需求更大。上下文较小的模型先选精简档，并缩短补充证据。

## 新模型的验收

选用全部评测题，保存模型名、服务版本、运行日期、预算、提示词和答案。按每题 `rubric` 逐条人工评分；至少单独记录对象正确、测法正确、机制适用、反证可执行、未造事实、隐私边界、生产指令边界。不通过的题保留并修正提示或知识，不能只删掉难题。

`tools/evaluate.py` 只检查本地剧本检索与知识概念是否进入材料，不会消耗 API，也不能给出模型专业准确率。真正的模型表现需要实际调用和人工评价。

# DeepSeek 连接排查补充（2026-10-11）

DeepSeek 官方服务可使用 Chat Completions 协议，接口填写 `https://api.deepseek.com/chat/completions`。模型名以服务平台和[官方接入文档](https://api-docs.deepseek.com/)为准，第三方平台提供的密钥须配合同一平台的接口地址。

若点“测试连接”就提示运行环境阻止联网，应关闭受限预览服务，然后运行项目中的 `start-workbench.ps1` 启动普通本机服务。仅刷新网页不会改变后端进程的联网权限。重启服务后刷新页面。已保存的模型连接会自动恢复；没有保存的临时密钥需要重新输入。

0.3.1 将权限拒绝、DNS、证书、连接中断和超时分别提示，并区分认证失败、余额不足和服务繁忙。不会输出服务商原始错误内容或密钥，也不会自动重试产生重复请求。当前 90 秒是网络操作等待上限，不是整段推理的严格总时限；DeepSeek 的非流式保活空行能够正常解析。

## 本机连接保存（0.6.0）

Windows 将模型密钥以当前用户 DPAPI 加密存入 `%LOCALAPPDATA%/SeparatorAtlas/settings.local.json`。页面只取回地址、模型、协议、预算、发送确认和密钥存在状态，密钥栏留空可沿用。保存新密钥可更换，“删除已存密钥”删除加密凭据；地址或协议变化导致最终接口不同则不复用。优先级为本次输入、匹配目的地的已保存密钥、匹配目的地的环境密钥。换电脑或 Windows 用户需重新保存密钥。

字号和分析深度也保存在本机配置中。`SEPARATOR_CONFIG_DIR` 可隔离测试配置。非 Windows 可保存非秘密设置，密钥采用原有环境变量方式，不退回明文持久保存。

系统方案通常与普通问答一样执行检索计划及最终回答两次调用，追加 `agent/system_plan_protocol.md`，不自动确认共同因素或唯一根因。知识迁移包包含这份协议。
