# 系统方案、提问节奏与小屏对话改造计划

日期：2026-10-30。状态：已执行；实施结果与验证边界见 `版本说明_0.6.0.md`。下文保留方案设计及原始目标。

## 1. 改造目标与已确定要求

以现场工程师持续分析质量问题为主要使用场景。支持单一原因、多个因素共同作用，以及证据暂时不足以区分多个解释的情况。让用户能够及时获得阶段性系统方案，同时继续深入、验证和交接。

本轮需求清单：

| 编号 | 已确定要求 | 计划交付 |
| --- | --- | --- |
| R1 | 系统方案按钮放在“分析材料”右边 | 两个按钮相邻，窄窗口中也保持顺序；证据足以形成阶段方案时高亮 |
| R2 | 不必先找到唯一根因才出方案 | 保留竞争解释、可能共同作用、关系未明三类关系；方案说明适用条件和验证方法 |
| R3 | 减少过细、重复、无止境追问 | 默认现场排查节奏，围绕下一步行动提问，用户可切换深入分析 |
| R4 | 14 寸屏幕上回复区域太小 | 优先分配空间给回复，缩减固定栏占用，适配实际窗口和缩放 |
| R5 | 输入框一直保持一行 | 固定单行可见高度，发送按钮同一行，长文本完整保留 |
| R6 | 横向拖拽可以继续覆盖星球 | 星球达到最小占位后，对话继续向左覆盖，最大接近工作区全宽 |
| R7 | 前端暂时去掉本地引导选项 | 默认模型对话；保留后台本地能力，便于以后恢复 |
| R8 | 未配置 API 要提醒配置 | 保留输入草稿，提供直达模型设置的入口，配置完成回到原对话 |
| R9 | API 可以保存，重开不必重新填写 | 模型地址、协议、模型名和密钥持久保存；密钥由 Windows 当前用户范围保护 |
| R10 | 修改并上传后可以恢复旧版本 | 改造前固定 v0.5.1 基线；程序、知识和会话分别安排备份与恢复 |
| R11 | 后续确认取消亮色界面 | 仅保留深色星空；删除首页“模型”副标题；底部署名两行完整可见 |

首页保留星云与节点的视觉形态，保留现有暗色星空。知识点亮、外部知识流星、知识库、关系图谱、FTA、保存和载入等既有能力纳入回归验证。

## 2. 当前程序的已核查情况

- 当前本地 HEAD 与已知 origin/main 均为 `08d4079d2b06a3137daeedd77a96daa18ec0c632`，日期为 2026-10-24，程序版本为 0.5.1。本次没有进行新的远端同步。
- 当前输入正文最小高度为 63px，输入区域另有模式选择、发送行、快捷键提示及边距；聊天标题固定 76px，工具栏可以多行换行。
- 对话宽度被限制在工作区的 32%—68%，无法继续覆盖星球。
- 后加载的布局样式存在主区域最小高度 590px；窗口宽度不超过 800px 时，旧布局会把较高的星球和对话上下排列。页面缩放也可能触发这些条件。
- 现有设置只保存地址、模型名、协议和知识预算，不保存页面内填写的密钥。
- 现有候选记录允许多个原因，但缺少显式的系统方案请求、因素间关系和方案充分度状态。
- 普通文字“给系统方案”可能被当成用户现场陈述；现有整理结论操作会跳过模型补查，且生成正文可能覆盖原待答问题。
- 当前 FTA 主要记录问答路径和不同回答分支，不等于已经验证的物理故障逻辑树。不同分支的答案不能直接合并成同时成立的因素。

## 3. 系统方案功能

### 3.1 入口与高亮

1. 按钮名称为“生成系统方案”，紧邻“分析材料”右侧。
2. 空会话时提示先描述问题；存在问题描述后可以点击，不需要凑足问答轮数。
3. 普通状态表示随时可生成初步方案；高亮表示当前材料足以形成更有针对性的阶段方案，不表示根因已确认。
4. 默认以约 4—6 轮有效问答作为首次重点评估区间。信息一开始就足够时提前提示；不足时不能仅凭轮数高亮。
5. 有效问答是新增观察、对照、检查结果、重要限制或有效更正。继续、总结、重复陈述及单纯未知回答不作为新增证据计数。
6. 充分度结合对象和现象是否清楚、主要区段或机制是否有依据、是否能给出针对性措施与验证路径。关键冲突仍存在时，显示初步方案状态，并明确冲突。
7. 多次未知说明需要现场取证时，提供检查计划；不为等待按钮高亮而继续盘问。
8. 提示适度，避免每轮闪烁、弹窗或重复总结；新证据或分支变化后重新评估。
9. 直接输入“先出系统方案”等明确请求，与点击按钮使用同一种行为。请求中同时包含的新现场信息仍需单独提取和保存。

### 3.2 方案内容

方案默认先呈现最值得执行的事项，详细条件可展开。按实际问题组织，不机械填满所有栏目：

- 当前问题和适用范围：目标指标、已知事实、未决条件。
- 因素与机理：哪些是竞争解释、哪些可能共同作用，证据分别是什么。
- 优先控制：当前阶段可以先评估的控制措施及目的。
- 针对性改善：每项措施对应因素、机理、适用条件、先后依赖和副作用。
- 验证安排：对照、观察项目、必要重复、测量限制、成功与停止标准；需要识别交互作用时采用适当组合试验，不能一律强制单因素。
- 持续控制：措施验证有效后，如何进入检查、维护、控制计划和复发监测。

主响应始终对应本次目标。分析掉粉时，先定义掉粉评价；滑移测量可作为机制响应。漏涂或覆盖率只有在存在相关路径时才纳入。不得把候选设备改造直接表述为根治，不凭空给出生产设定值、样本量或验证结果。

### 3.3 知识、对话与 FTA 衔接

- 系统方案使用独立动作类型，不直接复用“整理结论”。
- 生成前针对当前有效候选补查机理、控制点、改善措施、相关条件和副作用；不限于最后一个问题的检索主题，也不扫描整库后无差别堆砌。
- 方案记录生成节点、当前事实范围、引用知识和版本。更新方案保留旧版，便于比较。
- 方案生成不清空原待答问题和选项；下一次回答字母仍能对应原问题。
- 方案正文不是现场事实，建议检查不算已执行。方案中的编号和问句不被误识别成新的访谈选项。
- 同一方案生成期间避免重复提交；失败后保留原会话、草稿和待答问题。
- 分支切换、删除、恢复、存档和载入均遵循当前路径。另一分支的答案和验证结果不自动进入当前方案。
- 候选因素关系独立保存，不能通过合并不同问答分支制造“共同作用”的证据。

## 4. 每轮提问颗粒度

默认采用现场排查节奏，智能体自动调整。用户可以用自然语言要求先给做法、继续深入或解释机理；界面提供轻量的“深入分析”选项，放入分析偏好，避免增加一整行常驻控件。

### 4.1 默认原则

1. 每轮围绕一个会改变下一步行动的判断，可以合并紧密相关的事实，不把一个判断拆成一串机械小题。
2. 前期先定位现象、异常区段、正常与异常差别、近期变化；用户一次给出多项信息时全部接收。
3. 只在答案影响措施选择、验证设计或关键风险判断时深入参数、设备细节与微观机制。
4. 若不同答案不会改变下一步行动，该问题通常延后或省略。
5. 用户不知道、没有测量时，转为取证任务，不换一种问法继续索取同一项未知。
6. 已有可执行验证方向时，可以先形成阶段方案；现场反馈回来后继续深入。
7. 真正影响判断的冲突需要澄清；不能为了减少轮次省掉关键区分。
8. 选项用于辅助表达，可支持多选、部分成立、未知及自由描述。独立共存因素不被强制设成互斥选项；字母解析需与实际问题绑定。
9. 日常回答保持简短，不每轮总结；明确要求方案、机理解释、总结和交接时使用对应输出模式。

### 4.2 案例校准

用单一原因、多因素共同作用、竞争解释未分清、反复未知、用户主动提供大量信息等场景比较改造前后。重点看重复问题数、无行动价值的问题数、能否及时转为取证，以及关键事实是否遗漏，不以轮次越少越好作为唯一指标。

## 5. 小屏布局与输入区

### 5.1 回复区域优先

- 页面按实际可用窗口高度布局，移除会迫使主页超出窗口的硬最小高度；长对话由消息区域滚动。
- 缩减聊天标题、上下留白、恢复状态、版权说明等固定占用；保留必要信息和作者署名。
- 去掉“模型对话 · 模型对话”等重复标签；知识依据默认紧凑折叠，可按需展开。
- 工具栏保持紧凑。分析材料与系统方案始终相邻；低频操作可进入“更多”，不能因新增按钮不断换行挤压正文。
- 外部搜索设置可在浮层展开，保持联网状态可见，避免大段设置长期占据消息区。
- 主对话只保留一个主要纵向滚动区域。消息正文不另设很小的固定高度；表格等特殊内容保留必要的独立横向滚动。
- 用户正在回看历史时不强制拉到最底部；提供新消息或返回底部入口。

### 5.2 输入固定一行

- 输入区始终保持单行可见高度，建议初值 40—44px，发送按钮同一行。
- 不因输入内容自动增高。长文本或多行粘贴完整保留，通过输入框内部滚动编辑；不截断、不静默丢失。
- 保留 Enter 发送、Shift+Enter 换行；中文输入法选词的 Enter 不触发误发送。
- 常驻模式下拉框移除，快捷键说明转为轻量提示。

### 5.3 字号与缩放

- 正文初始字号建议 16px，支持 18px、20px等阅读档位；字号控制放在阅读偏好中。
- 正文字号同步覆盖问答选项和正文表格，避免正文变大后选项仍过小；不连带放大所有装饰区。
- 记住阅读字号和对话宽度，窗口变小时重新限制在可用范围内。
- 适配操作系统缩放、浏览器缩放及桌面窗口，不能仅根据“14寸”推断可用尺寸。
- 有效宽度降至 800px 附近时以对话优先，取消先显示大块星球、再滚动找到对话的旧式堆叠。

### 5.4 界面最终要求

后续确认取消亮色模式，删除主题开关。保留深色星空、字号与深度偏好，去掉首页“模型”字幕，底部署名两行完整可见。

## 6. 对话覆盖星球的连续拖拽

1. 正常宽度下保持星球和对话并列，可考虑默认给对话约 55%—60% 的宽度，最终以实测为准。
2. 向左拖动时先缩小星球的占位；约 280—320px 为初始最小占位设计范围。
3. 到达最小占位后继续拖动，对话覆盖星球，最大接近工作区全宽，保留少量外边距及可操作的恢复入口。
4. 对话背景保持足够不透明，星光和线条不影响文字阅读。
5. 反向拖动可恢复星球可见范围；保留双击恢复和键盘调整，提供明确的恢复布局操作。
6. 拖拽条在最大宽度时仍可访问；星图搜索、标题、节点卡片等不能压到对话上方。
7. 被覆盖的星球控件不拦截鼠标、不进入错误的键盘焦点；可见区域的星图交互正常。
8. 知识高亮、外部知识流星和引用记录仍正常更新；星球重新露出时可查看，完全遮挡时可减少动画绘制负担。
9. 窗口缩放、最小化恢复、重新打开后，宽度应恢复或限制在当前窗口可用范围内，不能使输入和拖拽入口丢失。

## 7. 默认模型对话与 API 持久保存

### 7.1 前端模型入口

- 新对话默认使用模型，移除本地引导选择项及“切换本地引导”的提示文案。
- 后台本地引导能力保留，作为未来可恢复的功能；模型失败时不自动改用本地引导生成貌似模型的回答。
- 未配置时显示“请先连接模型”，提供直达设置入口，保留已输入内容。
- 历史本地引导记录仍可阅读和载入，来源标签保持真实；后续新回答使用模型。
- 知识浏览、图谱浏览及本地保存/载入仍能在未接模型时使用。

### 7.2 保存体验

1. 设置中提供“保存连接”，保存服务地址、协议、模型名、知识预算和 API 密钥。测试连接与保存结果分别明确显示。
2. 页面刷新、关闭重开及本机服务重启后，恢复连接配置；同一 Windows 用户下，桌面和浏览器入口使用同一份本机配置。
3. 密钥栏显示“本机已保存”，提供更换和删除操作，不需要将已保存明文重新返回前端。
4. 不在页面启动时无提示地反复调用付费接口。区分“已配置”“上次测试成功”“本次连接失败”，不把存在配置当成服务此刻在线。
5. 地址或协议发生实质变化时，不自动把旧密钥用于另一服务；模型名变化沿用同一服务配置但应允许重新测试。
6. 发送范围选择绑定对应服务保存；改变服务后重新检查。保存模型配置不能自动开启外部搜索，也不能扩大自建知识的发送范围。
7. 现有环境变量接入继续兼容，明确临时填写、已保存配置和环境变量的选用顺序，避免混用服务地址与密钥。
8. 未配置、认证失败、余额不足、超时、服务中断分别提示，保留草稿和分析状态，不要求因一次网络失败重新输入密钥。

### 7.3 本机存储方案

- 建议使用 Windows 当前用户范围的 DPAPI 加密模型密钥，由本机后端读写，保存在用户应用数据目录中。当前项目已有用户应用目录可沿用。
- 普通地址、模型名等与凭据关联保存。前端只获取配置和“是否存在已保存密钥”的状态。
- 密钥不进入 Git、源码、普通浏览器明文存储、对话存档、分析材料、知识包或发布包。保存、删除接口使用现有本机来源与请求令牌检查。
- 保存采用完整写入后替换等方式，避免意外关闭造成原配置损坏；读取失败明确提示，不能静默降级为明文保存。
- 换电脑或换 Windows 用户时需要重新配置密钥；程序与知识仍可迁移。
- Tavily 是独立凭据。本轮重点为模型 API 保存，不能用模型密钥替代检索密钥或自动启用联网检索。

微软对当前用户范围保护的说明：[CryptProtectData](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)。

## 8. 旧版本保留、备份与恢复

### 8.1 当前基线

当前可定位基线为 v0.5.1，对应 [08d4079](https://github.com/lhzlhz380809337-cpu/separator-atlas/commit/08d4079d2b06a3137daeedd77a96daa18ec0c632)。正常提交并上传新版本会增加历史记录，旧提交仍可查阅和恢复。

实施开始前：

1. 核对工作区及远端，确保当前基线准确；保留用户在此后的独立修改。
2. 为基线补齐明确的 v0.5.1 标签；若已有同名标签则核对目标，不移动旧标签。
3. 在 `codex/` 开头的独立开发分支实施，按模块提交，便于定位问题和撤回局部变化。
4. 在本机保存包含源码、前端、桌面入口、已纳入版本的知识及依赖说明的完整程序备份。桌面 exe 依赖其他项目文件，仅备份 exe 无法恢复完整程序。
5. 将当前对话和 FTA 导出为可载入 MD 与 JSON；单独备份知识投递、正式案例库及其他本机自建内容。浏览器本机记忆不等于 Git 备份。

### 8.2 新版本发布

- 建议新功能版本使用 v0.6.0，发布前统一服务端、页面、桌面程序、说明和清单中的版本号。
- 验收通过后按正常历史提交上传，不改写或强推覆盖旧历史。
- 为新版本建立标签、更新说明和完整程序包，同时保留旧版本包及恢复说明；已有源文件和秘密凭据继续留在本机边界内。
- 保留现有桌面入口和浏览器入口，发布清单与实际文件一致。
- 旧会话升级前备份保持原样；新版本兼容读取旧会话。新增方案/关系字段的格式变化要版本化，并说明回到旧版时能保留哪些信息，不能假设旧版理解所有新字段。

### 8.3 发生问题时

- 可先启动独立目录中的 v0.5.1 完整程序继续工作；启动前确认没有新版本服务占用同一端口，避免旧入口打开的实际还是新服务。
- 使用升级前兼容旧版的会话备份恢复；升级后新增的会话另存，不覆盖或丢弃。
- 代码层面可以通过新增撤回提交恢复行为，也可只撤回某个模块，保留排查历史。
- 代码恢复不自动恢复被 Git 忽略的本机案例、知识、凭据和浏览器数据；这些按上述本机备份分别恢复。

GitHub 提供按发布版本和标签查看历史及下载对应文件的入口：[查看版本与标签](https://docs.github.com/en/repositories/releasing-projects-on-github/viewing-your-repositorys-releases-and-tags)。

## 10. 验收清单

### 10.1 屏幕与可读性

以实际网页内容视口为准，分别检查桌面入口和浏览器入口。显示器物理分辨率、Windows 缩放和浏览器缩放共同决定内容视口，不能把它们当作互不相关的测试参数。

| 实际内容视口示例 | 目标 |
| --- | --- |
| 1536×760 | 常规笔记本阅读与拖拽 |
| 1280×620 | 优先验收，争取回复区域至少约 350px 高 |
| 1093×560、1024×500 | 小窗口和更高缩放，1024×500 争取至少约 250px 回复高度 |
| 800×450 | 不再出现星球先占数百像素导致对话在屏幕下方的情况 |

上述回复高度是实现目标，不是已完成的实测结果。覆盖 100%/125%/150% 浏览器缩放、常见 Windows 缩放及正文 16/18/20px 的代表组合，记录实测视口，避免重复放大后误报覆盖范围。

- 长回复可连续读多行，输入和发送始终可见；不通过缩小字体解决空间问题。
- 空会话、25 轮历史恢复、长方案、多个选项、知识依据展开、错误提示均不压扁回复区域。
- 输入框长文本粘贴、多行内容、中文选词不丢字、不误发送，外部高度保持单行。
- 对话可拖至覆盖星球，反向恢复、双击恢复、键盘调整及窗口尺寸改变都正常。
- 材料与方案按钮相邻；其余功能可找到，浮层和菜单可关闭。
- 用户回看历史时不会被新回复强行拉走；可明确返回最新消息。

### 10.2 模型配置

- 未配置时保留草稿并引导设置；不出现本地引导选择项。
- 保存后刷新页面、关闭重开、重启本机服务仍可使用保存配置；桌面与浏览器入口一致。
- 更换服务不会误用旧密钥；更换和删除密钥真实生效。
- 密钥不出现在响应正文、日志、分析材料、会话、Git 和发布文件中。
- 连接错误有明确提示，已有配置和对话不丢失。
- 无需密钥的本机模型及现有环境变量方式保持兼容。

### 10.3 系统方案与对话

- 单一原因、多个共同因素、竞争解释未区分三种案例均能输出合适的阶段方案。
- 四轮重复或未知不能误亮为证据充分；首条信息完整可以提前提示；自由文字请求无需等待轮数。
- 一次提供多项信息时不重复提问；未知转为检查任务；深入模式仍可处理关键细节。
- 生成方案后回答原问题的 A/B 仍对应正确；多选和自由补充可正确记录。
- 方案请求不变成现场证据，方案建议不变成已执行检查，未排除不变成已证实共同作用。
- 分支、删除恢复、MD/JSON 保存载入后，事实、待答问题、方案范围和高亮状态对应正确。
- 生成失败保留原状态；材料包与星图高亮对应实际使用的知识。

### 10.4 发布与恢复

- 已有知识数量和链接无意外减少；现有测试及此次新增的必要回归通过。
- 可从旧版程序包和升级前会话恢复，启动时不会复用错误版本的后台服务。
- 发布包包括必要程序和依赖说明，排除密钥、原始公司资料和私人会话。
- 版本号、提交、标签和说明一致，旧版本入口可明确找到。

### 10.5 最终界面调整

按后续要求取消亮色主题及其开关，所有页面继续使用深色。首页“与星云对话”下方不显示无意义的“模型”文字。底部署名与 QUALITY · CONTINUOUS IMPROVEMENT · 2026 均保留，并预留底部空间。

执行结果与实际验证范围见 `版本说明_0.6.0.md`；本文件保留早期方案供追溯，主题相关旧规划已被以上要求替代。
