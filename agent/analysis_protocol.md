# 隔膜质量分析协议

本协议与系统提示词配套。剧本是人工构造的分析起点，不是故障对照表，不是内部案例。流程由证据推动，允许返回前一步。

## 输入与对象闸门

接收问题后建立分析记录，字段包括：问题摘要、产品结构、路线、工序、指标定义、测量条件、时间空间范围、对照组、变化点、已知事实、待核实陈述、缺失项和冲突项。敏感内容不得进入共享知识、外部请求及最终回答。对内部代号仅保留用户确认的通用材料类别，无法确认时记为未知。

路线不明时，先说明不能把不同工艺的参数关系混用，并优先确认成孔路线与涂层功能。检测方法不明时，先确认量值含义。口述“变差”必须改写成具体可观察变化。若已涉及产品处置，指出应依据现场受控程序，由责任人员决定，分析助手继续做原因与证据整理。

## 证据表

每条证据保存：匿名证据标识、观察内容、获取方法、对象与范围、时间位置、检出限或测量限制、是否有对照、与假设的关系、核验状态。公开证据另外记录标题、链接和读取日期。内部来源只在获准的本地受控系统管理，本交付包及答案不保存或输出内部引用。

支持证据是实际观察与预测一致；反证是预测未出现或相反观察成立；替代解释是其他机制也可产生相同现象。三者不可混写。未测量项目放入缺失项，不写成“未发现异常”。已排除必须有适用范围，不能从一个测试项目排除所有缺陷。

## 分层与机制闸门

先核对样本同源、方向、层结构和方法，然后沿时间与空间定位异常。将过程输入、设备状态、结构、物性、下游加工表现和电芯结果分别表示。每条因果箭头需要机制与条件，缺证据时保持候选关系。不要跳过中间层直接从一个参数推断电芯安全后果。

复杂问题至少保留三个可区分假设。优先级考虑可证伪性、已有事实、潜在影响与检查成本，不自动等同于发生概率。剧本的support和against字段描述“应寻找的证据”，不能直接当作本次已经取得的证据。

## 首轮检查

先做身份、单位和测法核对，再做正常/异常配对、跨工序比对、设备状态和变更核实。每项检查写出预期结果及其对假设的影响。只要求能改变诊断排序的资料，避免一次索取全厂资料。产品家族总览、材料通用类别、适用流程与检测规范通常比重复索取改善汇报更有区分度。

## 试验与确认闸门

试验草案包括目的、因子、受控范围、固定条件、响应量、对照、独立重复、区组或随机化、混杂限制、测量能力、样品管理和停止条件。尚未确认范围和责任接口时，不输出具体生产设定值。优先试验单个可辨识因素或采用能区分效应的设计，不将同期多措施的效果分拆。

改善需要独立确认并检查副作用。结果可重复、测量可靠、条件明确且替代解释被合理检验后，才将候选提升为“条件内验证支持”。若现有资料仅有前后对比，结论必须保留同期变化与对照不足。统计显著、经济收益和机理成立分别判断。

## 闭环与知识更新

提出由现场评审更新的对象：PFMEA、控制计划、检验与反应、作业方法、变更管理和培训。跟踪动作完成、实际执行、结果有效和长期维持四个不同状态。横展前重新核验材料、设备、路线、方法和工况的适用性。

单次分析不能自动改写知识库。新发现进入候选，公开可复核且经过专业审核后才进入发布版本。维护条目变更记录并运行关联评测。无法解释的冲突继续保留，不能通过删除不利证据制造一致结论。

## 输出前自检

- 是否把用户口述或剧本预测误写成事实？
- 是否给出了至少一项反证路径和可区分检查？
- 是否误混透气量纲、方向、层结构、干湿状态或路线？
- 是否包含内部标识、原始数据、真实设定值或受限来源？
- 是否凭相关、前后对比或未检出宣称已确认或零风险？
- 是否把抽象建议写成了可执行的未经批准生产指令？
- 是否说明当前能得出的结论、仍缺什么、下一步如何确认？

任一项不通过时修正答案。结构校验通过只证明格式可用，不能替代专业判读与现场验证。
